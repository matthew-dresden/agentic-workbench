# E11-F1: Migrate the `workbench-backlog-builder` catalog entry

## Status: in-queue

## Description

Bring the `workbench-backlog-builder` catalog entry into Section 3.5 soft-spot
compliance. The entry's manifest XML lives at
`repo-specs/common/software-development/requirements/workbench-backlog-builder/workbench-backlog-builder-marketplace.xml`
and the legacy author-facing README lives at
`catalog/workbench-backlog-builder/README.md`. The XML filename and the
catalog directory name agree, so no entry-name rename is required: the
canonical entry-name is `workbench-backlog-builder`.

Today's `<catalog-metadata>` block carries `display-name`, `type`,
`description`, `owner-name`, `owner-email`, `keywords`, and `version` as
attributes but is MISSING the REQUIRED `<name>` element. The single
referenced `<project>` revision pins
`refs/tags/software-development/requirements/workbench-backlog-builder/>=0.1.0,<1.0.0`
against the inherited `example-org` remote (resolved via
`repo-specs/git-connection/remote.xml`); the PEP 440 last-path-component
of that monorepo-prefixed constraint is `>=0.1.0,<1.0.0`, which IS PEP 440
compliant.

This feature decomposes into a single story (`E11-F1-S1`) with a single
task (`E11-F1-S1-T1`) per the spec's "one task per non-conforming entry"
rule.

Spec source: spec Section 9b Phase 1; Section 3.5 soft-spot rules 1-5.
