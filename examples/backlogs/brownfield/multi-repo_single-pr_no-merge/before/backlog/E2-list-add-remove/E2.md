# E2: `mpm list` + `mpm add` + `mpm remove`

## Status: in-queue

## Description

The first consumer-facing feature epic of the mpm dependency-manager release.
Implements three new top-level commands plus two shared helpers:

- **`_parse_catalog_metadata()`** -- shared helper that reads a
  `*-marketplace.xml` file, validates the `<catalog-metadata>` block against
  soft-spot rule 1 (required fields, no duplicate children, exactly one block
  per file), and returns a typed `CatalogMetadata` dataclass with `name`,
  `display_name`, `description`, `version`, `type`, `owner_name`,
  `owner_email`, and `keywords` fields. Errors on missing required fields,
  duplicate children, multiple blocks, and malformed XML; warns on missing
  recommended fields.

- **`derive_source_name()`** -- shared helper that normalises a
  `<catalog-metadata><name>` value into the source-name token used inside
  `MPM_SOURCE_<source-name>_{URL,REVISION,PATH}` triples. The rule is
  unconditional: always lowercase, always replace `-` with `_`. Same input
  always produces the same output (soft-spot rule 2).

- **`mpm list`** -- discovers catalog entries by walking
  `repo-specs/**/*-marketplace.xml` inside the resolved manifest repo.
  Default output is one entry name per line, pipeable into `mpm add`.
  Flags: `--detail`, `--tree`, `--max-depth N`, `--all-versions`,
  `--limit N`, `--no-limit`, `--since-version <spec>`,
  `--format {names,json}`, positional `<substring>`, `--regex <pattern>`,
  `--match-fields <csv>`, `--no-filter-required`. Empty-catalog and
  zero-match paths exit 0 with stderr notes.

- **`mpm add`** -- adds one or more catalog entries to a `.mpm` file by
  reading each requested entry's `<catalog-metadata>`, resolving the
  default-or-explicit `@<spec>`, and writing the three
  `MPM_SOURCE_<source_name>_{URL,REVISION,PATH}` lines. Creates the
  destination file with the standard header if missing. Collision detection
  (against the requested set AND existing source-name blocks) is hard-error
  without `--force`. `--dry-run` prints the diff with no file change. Zero
  PEP 440-valid tags for the default-spec path is a hard error with a
  remediation pointer.

- **`mpm remove`** -- inverse of `add`. Accepts either the source name
  (e.g., `foo_bar`) OR the original entry name (e.g., `Foo-Bar`); both
  normalise via `derive_source_name()` before lookup. Locates every
  `MPM_SOURCE_<normalized>_{URL,REVISION,PATH}` line (lines MAY be
  non-contiguous in hand-written files); fewer than three matching keys is
  a hard error. Preserves line endings (sniffed per-file; mixed normalises
  to `\n` with warning), collapses runs of three or more blank lines to two,
  and ends the file with exactly one trailing newline. `--dry-run` prints
  the diff with no file change.

Spec source: `spec/mpm-list-add-lock-features-spec.md` Sections 4.1, 4.2,
4.3, and 3.5 (soft-spot rules 1, 2, and 3).

E2 depends on E1 (resolver semantics, URL canonicalisation, shared CLI args).
E3 (lockfile + install extension), E4 (outdated + why), and E5 (doctor +
catalog audit) all consume E2's helpers (`_parse_catalog_metadata`,
`derive_source_name`) for their own command implementations.
