# E5-F3-S1: `mpm validate metadata` sub-subcommand implementation

## Status: in-queue

## Description

Single-task story. Adds the new `metadata` sub-subcommand to today's
`mpm validate` command (`src/mpm_cli/commands/validate.py`), wiring
in the in-repo subset of soft-spot checks (1, 2, 3).

The sub-subcommand mirrors the surface of its siblings:

- `mpm validate metadata [--repo-root <path>] [--format {text,json}]
  [--no-color]`
- Default `--repo-root` is cwd (same as `mpm validate xml`).
- Walks `repo-specs/**/*-marketplace.xml` inside the supplied root.
- Errors on soft-spot 1 (missing REQUIRED fields, duplicate child elements,
  multiple `<catalog-metadata>` blocks) and soft-spot 3 (entry-name
  collisions across XML files).
- Warns on soft-spot 1 (missing RECOMMENDED fields) and soft-spot 2
  (source-name normalisation drift and out-of-charset entry names).
- Exit 0 if no errors; exit non-zero if any error. Warnings alone do not
  fail (matches `mpm validate marketplace` semantics; `--strict` is not
  introduced here -- catalog authors get strict semantics from
  `mpm catalog audit --strict`).

Spec source: spec Section 3.5 and Section 13 decision 10.
