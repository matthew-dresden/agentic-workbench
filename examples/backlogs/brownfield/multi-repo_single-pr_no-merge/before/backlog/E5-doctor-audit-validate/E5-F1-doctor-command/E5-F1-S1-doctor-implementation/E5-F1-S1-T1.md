## Description

Create the new `mpm doctor` subcommand skeleton in
`src/mpm_cli/commands/doctor.py` and register it in
`src/mpm_cli/cli.py`. Implement the first five of the eleven subchecks
defined in spec Section 4.6:

1. **`.mpm` / `.mpm.lock` consistency** via `mpm_hash`. `.mpm`
   absent => hard error (`"no mpm workspace in <cwd>: '.mpm' not
   found"`, ERROR shape). `.mpm` present but `.mpm.lock` absent =>
   info-level notice to stderr ("No lockfile present; run `mpm install`
   to generate one."); skip checks 2-5 and 11; continue with checks 6-10
   (those are wired in by later tasks T2-T5).
2. **Hand-edit detection.** Recompute `mpm_hash` over `.mpm` + lockfile
   data per E3-F2's `compute_mpm_hash`. If the recomputed hash differs
   from the lockfile's `mpm_hash` field => error
   (`"mpm_hash mismatch: .mpm was hand-edited since the last 'mpm
   install'. Run 'mpm install --refresh-lock' to rebuild the lockfile."`).
3. **Orphaned lock entries.** For every source recorded in the lockfile,
   check that the matching `MPM_SOURCE_<name>_{URL,REVISION,PATH}`
   triple still exists in `.mpm`. Missing triple => error
   (`"orphan lock entry: source 'X' is in .mpm.lock but absent from .mpm;
   run 'mpm install' to prune (or 'mpm install --strict-lock' to keep
   the lockfile authoritative)."`).
4. **Branch drift.** For every lockfile entry whose REVISION resolves to
   a branch ref, query `git ls-remote refs/heads/<branch>` (subject to
   `MPM_RESOLVE_TIMEOUT` and the existing
   `MPM_GIT_RETRY_COUNT`/`MPM_GIT_RETRY_DELAY` policy). When the
   branch tip SHA differs from the lockfile-recorded SHA, emit info-level
   drift notice by default. `--strict-drift` promotes to error.
5. **Dangling SHA.** For every lockfile entry, run
   `git ls-remote --exit-code <url> <sha>`; non-zero exit => error
   (`"dangling SHA: <sha> is no longer reachable from <url>; the remote may
   have force-pushed or pruned the commit. Run 'mpm install
   --refresh-lock' to rebuild."`).

Argparse surface (this task adds the subcommand itself plus the flags
that subchecks 1-5 consume; T2-T5 add the rest):

- `mpm doctor [--mpm-file <path>] [--lock-file <path>] [--strict-drift]
  [--no-color]`
- `--mpm-file` default `./.mpm`; env `MPM_MPM_FILE` (shared with
  install, per E1-F4).
- `--lock-file` default derived from `--mpm-file` (matches E3-F1's
  derivation rule); env `MPM_LOCK_FILE`.
- `--strict-drift` -- boolean.
- `--no-color` -- existing convention.

The subcommand is implemented as `commands/doctor.py::doctor_command(args)`
returning an exit code. `cli.py` registers it in the existing argparse
subparser dispatch table.

Reuse, do NOT reinvent:

- `mpm_hash` computation from `core/mpm_hash.py` (E3-F2-S1-T1).
- Lockfile read from `core/lockfile.py` (E3-F1-S1-T1).
- Catalog-source flag definition from `core/cli_args.py` (E1-F4-S1-T1).
- Existing `git ls-remote` retry policy from `core/git_runner.py`
  (`MPM_GIT_RETRY_COUNT`, `MPM_GIT_RETRY_DELAY`,
  `MPM_RESOLVE_TIMEOUT`, `GIT_AUTH_ERROR_PATTERNS`).

Spec source: `spec/mpm-list-add-lock-features-spec.md` Section 4.6
subchecks 1-5; Section 7 (retry policy).

### Approach

1. **TDD RED (unit):** Write `tests/unit/test_doctor_consistency.py`
   with parametrized cases for the five subchecks. Each case constructs a
   minimal fixture (`.mpm` + optional lockfile) under `tmp_path` and
   asserts on the subcheck function's return value (e.g.,
   `_check_mpm_hash(workspace) == DoctorFinding(kind="error", ...)`). Run
   `uv run pytest tests/unit/test_doctor_consistency.py -v`; confirm RED.
2. **TDD RED (integration):** Write
   `tests/integration/test_doctor_consistency.py` that drives the full
   `mpm doctor` CLI via `subprocess.run` against a fixture workspace.
   Cover absent-`.mpm`, absent-lock, hash-mismatch, orphan-lock,
   drift-with-and-without-`--strict-drift`, and dangling-SHA paths. Real
   fixture git server (`tests/fixtures/git_server.py`) provides the
   reachable-SHA / unreachable-SHA distinction.
3. **TDD GREEN:** Implement `src/mpm_cli/commands/doctor.py` with:
   - A `DoctorFinding` dataclass (kind in {"info","warn","error"}, code,
     message, remediation).
   - One pure function per subcheck (`_check_mpm_hash`,
     `_check_orphan_locks`, `_check_branch_drift`,
     `_check_dangling_shas`).
   - A `doctor_command(args)` entrypoint that orchestrates the checks,
     prints findings, and returns exit code 0 unless any error.
   - Register the subcommand in `src/mpm_cli/cli.py`.
4. **TDD REFACTOR:** Extract any shared "load workspace state" logic
   into `src/mpm_cli/core/workspace.py` if it duplicates code that
   `mpm install` already uses; otherwise keep the helpers private to
   `doctor.py`.
5. **Integration:** End-to-end -- run the new CLI under a fixture
   workspace that exercises each of the five subchecks (info, warn,
   error). Record exit codes in the TDD Cycle Log.
6. **Docs:** Update `docs/cli/doctor.md` (NEW) with the subcommand
   reference, the five subchecks documented in this task (later tasks
   add 6-11), the `--strict-drift` flag, and the canonical error
   messages for each subcheck.
7. **Verify:** `uv run pytest tests/ -v && uv run ruff check src tests && uv run ruff format --check src tests && uv run mypy src && uv run bandit -r src -ll`.

#### Critical Rules (Violation = Automatic Rejection)

1. **NO FALLBACK LOGIC** -- If an operation can fail, it MUST fail loudly. Never catch an exception and silently continue. Never provide a default value when the real value is missing. Exceptions: the resolver's documented lockfile-catalog-source fallback for `mpm install` / `mpm doctor`, and the existing `git ls-remote` retry policy (`MPM_GIT_RETRY_COUNT` / `MPM_GIT_RETRY_DELAY`) -- both in `spec/mpm-list-add-lock-features-spec.md` Section 4 header and Section 7.
2. **NO SILENT FAILURES** -- Every error must produce a clear, actionable error message sent to stderr. Every error must result in a non-zero exit code. Never swallow exceptions. Never log-and-continue when the operation was required to succeed.
3. **FAIL FAST** -- Detect errors at the earliest possible point. Validate inputs before processing. Check prerequisites before starting work. Exit immediately on the first error with a message that tells the user exactly what went wrong and what to do about it.
4. **NO HARD-CODED VALUES** -- No URLs, paths, timeouts, retry counts, port numbers, hostnames, credentials, feature flags, or environment-specific values in source code. All constants live in `src/mpm_cli/constants.py`, never inline in source files. All configuration comes from environment variables, configuration files, or function parameters.
5. **NO TEMPORAL LOGIC** -- Never use `time.sleep()`, `asyncio.sleep()`, or any time-based delay as a synchronization mechanism. The existing `MPM_GIT_RETRY_DELAY` (wait between known-failed `git ls-remote` retries) is the ONLY allowed sleep-based wait in this codebase. Use readiness detection, event-driven callbacks, or polling with configurable timeouts everywhere else.
6. **ALL CODE MUST BE DYNAMIC AND INPUT-DRIVEN** -- No static data, no hard-coded test fixtures embedded in source, no magic numbers. All thresholds, limits, paths, and identifiers must be parameterized.
7. **NO BYPASS ANNOTATIONS** -- Never add `# noqa`, `# nosec`, `# type: ignore`, `# pragma: no cover`, or any annotation that suppresses a linter, type checker, or security scanner finding. Fix the finding instead. The mpm repo has a documented vendored carve-out for `src/mpm_cli/repo/` (the embedded repo-tool fork): mypy and bandit scope to non-vendored code only. This carve-out is a scope demarcation, NOT a bypass annotation; do not extend it to new paths.
8. **NO DASH-EMS IN CODE OR TESTS** -- Do not use the em-dash character (Unicode U+2014) in any source file, test file, or work-unit `.md` file. Use `--` (double hyphen) in comments and docstrings if a dash is needed. `workbench validate-backlog` rule 10 enforces this on work-unit files.

#### Security Rules

- **NO eval() / exec()** -- Never execute dynamic code from external input.
- **NO PROVIDER-SPECIFIC API CALLS** -- Per spec Section 3.6, mpm NEVER calls provider HTTP APIs (`api.github.com`, `gitlab.com/api`, etc.) and NEVER shells out to provider CLIs (`gh`, `glab`, `bb`, `tea`, `aws codecommit`, `az repos`). Every git interaction is via the `git` binary only.

- Include context in error messages: file paths, variable names, expected vs actual values, the operator's likely next step.
- Never catch and discard exceptions.
- Never call `sys.exit()` from library code; only from CLI command handlers in `src/mpm_cli/commands/` or `src/mpm_cli/cli.py`.
- Error messages follow the standard shape per spec Section 4: `ERROR: <one-line summary>` then optional context lines (wrapped at 80 cols), then a remediation line when applicable.
