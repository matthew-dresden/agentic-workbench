# E5-F1-S1: `mpm doctor` implementation (eleven subchecks)

## Status: in-queue

## Description

Implement `mpm doctor` in five atomic tasks. Each task is one source file +
one or more test files; tasks are sequenced so each adds a coherent slice of
behaviour to the same `src/mpm_cli/commands/doctor.py` file:

- T1 -- Consistency checks 1-5 (`mpm_hash`, hand-edits, orphan locks,
  branch drift, dangling SHA). Creates the `doctor.py` skeleton, the
  subcommand registration in `cli.py`, and the cross-check core. Also wires
  in the absent-`.mpm` / absent-lock branches and the `--strict-drift`
  flag.
- T2 -- Effective catalog source resolution + reporting (subcheck 6).
  Precedence: `--catalog-source` CLI flag > `MPM_CATALOG_SOURCE` env var
  > lockfile `[catalog].source` > none. Print so operator spots shell-profile
  leakage.
- T3 -- Completion-errors report + completion-script staleness check
  (subchecks 7 + 9). Reads `${MPM_CACHE_DIR}/completion-errors.log` and
  compares on-disk static completion-script hash to a fresh `mpm completion
  <shell>` invocation.
- T4 -- `--refresh-completion-cache` + `--prune-cache` flags (subchecks
  8 + 10). Cache invalidation + age-based pruning, plus advisory stale-lock
  report.
- T5 -- Remote reachability sanity check (subcheck 11). Iterates lockfile
  `<remote>` URLs, runs `git ls-remote --exit-code <url> HEAD` per URL,
  surfaces errors as diagnostics without failing the command.

Each task's tests cover both the success path and every documented error
path. AC-CYCLE evidence is required for every task: each one's cycle test
constructs a real workspace fixture (some with a lockfile, some without)
and runs the full doctor command end-to-end.

Spec source: spec Section 4.6 (doctor) and Section 3.6 (effective-source
surfacing).
